Two independent reviewers were given the same brief
([`odin/REVIEW_BRIEF.md`](https://github.com/unempyd/odin/blob/main/odin/REVIEW_BRIEF.md)):
review this repository against `odin/DIRECTION.md` and `odin/AGENTS.md`, do
not rubber-stamp. Four rounds have run.

**Round one.** Codex (`codex exec`, read-only) returned **NOT FINISHED**
with concrete file:line findings. A Claude review covered the consent and
durability sections before its session was rate-limited.

**Round two, on the fixed tree.** Codex again returned **NOT FINISHED** —
its remaining findings are the credential write primitive, the
handle-stale classification, the veto ordering, and the contract-level items
listed under [Deviations](/docs/odin/deviations). Claude returned **FINISHED
WITH MATERIAL DEVIATIONS** and independently reran all 13 proofs (13/13
reproduce and close), finding one contradiction between two checked-in
tests and one unlisted renderer writer.

<Callout title="Every material finding became a commit">
  Each item below is an `odin(fix-…)` commit with its own failing-first
  proof — not a note that something was fixed, a test that failed before the
  fix and passes after it.
</Callout>

## What both rounds found and closed

- Injected-dispatch recovery had no production caller (wired into the
  shared recovery method, runtime-level proof).
- The wallclock reader mis-parsed SQLite timestamps outside UTC (34,201,000
  ms for a one-second interval in Adelaide; both ends normalised).
- Two credential-copy paths bypassed the consent gate (gate moved into the
  copy primitive).
- Two hook checks were still fail-open (`=== true` everywhere).
- Exit waits settled on a disconnected PTY and mapped the unverified exit
  code to `exited`; tui-idle results accepted missing evidence; the boolean
  adapter said satisfied on silence (all removed).
- Worker observation minted `exited` from absence and read every inspection
  failure as "missing" (now only the owner's not-found answer counts).
- Widen/narrow of the network listener could race (serialised, consent
  re-read after a widen).
- Profiles that inherited Orca's automatic bypass values kept them (one-shot
  review migration clears values equal to the YOLO table; a user who chose
  the same value re-enables it once).
- Launch receipts still copied `requested` into `effective` in two paths
  (now `null` when unknown).
- Sub-agent rows defaulted to done when nothing was observed (now
  unverifiable).
- The proof runner accepted any nonzero exit as a reproduction (now requires
  the named assertion at the upstream commit).

## Round-two-only findings

- The credential copy could still be reached through retained-pane
  synchronisation, and revocation left the credential in the provenance
  file (gate moved into `writeRuntimeAuth`, provenance deleted on
  revocation).
- `terminal_handle_stale` was read as owner-proven absence although it
  describes the client handle graph (only the PTY host's `terminal_gone` or
  a resolved null counts now; the injected-sweep error is returned, not
  dropped).
- A retained idle title or ready prompt outranked a fresh first-party
  working status (the veto is consulted first).
- Two tests written by the original H commit contradicted the H1 review
  migration (reconciled to the chosen contract).
- `odin/OPEN.md` omitted the command-code title writer (now enumerated).

## Round three, on the tree after v0.1.0

Scope: the renderer-writer increments, the SSH boundary run, exit waits on
timeout, the Linux proofs, the upstream pull requests, and the CI and dependency
changes (brief items 13–18). **Both reviewers returned FINISHED WITH MATERIAL
DEVIATIONS.** Every item became a commit with its own proof:

- Operator maintenance that closes no residual was undisclosed — hence the
  "Outside the contract" section, `odin/outside-contract.json`, and a drift
  ratchet that fails on any future change outside `odin/`, `src/`,
  `docs/reference/` or the README. The README also stopped claiming "nothing
  else changed" of a diff that includes a docs-site migration.
- `odin/OPEN.md`'s renderer-writer enumeration was incomplete — every
  `setAgentStatus(` call site is now classified and the `title-spawn-bell.ts`
  launch seeds are named.
- A failed status-ownership probe could fail the launch, and the remote-runtime
  ownership verdict was never re-evaluated after the probe resolved, in either
  direction.
- The command-code done-settle window existed in two copies — now one shared
  module plus a ratchet.
- The `safeStorage` windowless guard threw before install and was not
  platform-scoped — now darwin-only, one warning, with the degradation written
  into [Deviations](/docs/odin/deviations) and `docs/reference/`.
- An exit wait still rejected on absence instead of resolving the silence
  verdict.
- The command-code reader-side precedence rule was undisclosed.
- Four things the tree did not admit to: no cost/token accounting anywhere in
  the orchestration tree, two adjacent local liveness vocabularies,
  `terminal_gone` carrying two evidentiary strengths, the surviving
  `stateStartedAt` clock comparison, and an M proof file name that did not match
  the test.
- The proof runner mis-parsed `--only` and wrote per-run debug logs into the
  tracked proofs tree; two `.after.txt` notes claimed a `tc:web` baseline that
  was not true.
- The SSH driver's phases 4/6/7 could pass without the client ever observing the
  loss, and the Linux run had no checked-in runner.

Fixing those surfaced five further residuals, each with its own manifest entry
and failing-first proof: **I3** (Cursor's launch receipt was never checked
against the installed CLI), **I4** (a static-catalog fallback labelled
`source: 'probe'`, and memoised probe failures), **O3a** / **O3b** (a structured
worker's own host-owned `unverifiable` treated as absent on release;
`terminal_gone` overloaded across four unrelated failures), **N2** (the
schema-skew probe never registered v42's `exit_code` column), **G3** (the
credential mirror's no-consent branch still read and persisted the credential;
revocation deleted a retained pane's own file), and **show-contact-loss** —
found against a real VPS, not by inspection, when the strengthened SSH driver
ran and `terminal show` kept answering `connected: true` through a 90-second
transport drop.

## Findings raised but deliberately not changed

With the reason each time:

- The liveness projection keeps `unattached`, `missing`, and
  `identity_changed` as wire values beside `live / unverifiable / exited`
  because existing tests pin them as distinct client-facing states.
- `orca serve` and `orcad --bind` bind wide by explicit operator command.
- Positive on-screen evidence — an explicit idle marker or ready prompt the
  agent paints — remains tier-1 evidence.

These are the same items named in [Deviations](/docs/odin/deviations),
stated there as the record of what remains open at v1.0.0 by decision
rather than by oversight.
