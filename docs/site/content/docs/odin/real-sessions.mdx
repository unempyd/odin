Unit tests prove a function's contract. They don't prove that a real agent
CLI, launched by the real orchestration code, on a real headless host,
actually behaves the way the contract says. `odin/proof/real-sessions.mjs`
does that: it drives real `claude`, `codex`, and `grok` CLIs through Orca's
own `orchestration worker-start` on a headless `serve` host with an isolated
profile, and records the run.

  the repository — not a description of a run, the run itself.

The other honest crash-path answer, `operation_unknown` for a receipt still
pending at the crash, is pinned by upstream's own unit tests (see
[`odin/VERIFIED.md`](https://github.com/unempyd/odin/blob/main/odin/VERIFIED.md)),
not by this driver.

## Two things a unit test can't show

**The [H](/docs/odin/residuals) contract acting on a real profile.** A run
whose grants were written without `agentBypassDefaultsReviewed` had them
cleared on load because they equal Orca's former automatic values verbatim,
and the Codex worker parked on its approval prompt instead of settling
(`real-sessions.2026-09-14T15-05-30-764Z.json`, kept as evidence).

**The operator's own agent configuration is outside Odin's contract.** The
Claude worker completes even in the safe-default phase because this
operator's Claude config auto-approves; the argv still carries no flag from
Odin. Odin controls what Orca launches with — it does not, and cannot,
control what an agent's own configuration decides once it is running.

## Not covered

Windows and Linux hosts (macOS only), a third agent settling to compare
against Claude and Codex (Grok's quota was exhausted), and Orca's mobile app
paired against an Odin host. These gaps are named again, with their cost, in
[Deviations](/docs/odin/deviations).
